# Codex Token Report

本地、只读地扫描 Codex 会话日志，按天统计 input、cached input、cache write、output
token，并按照 OpenAI 官网公布的价格计算：

- 逐请求 Standard/Fast API 等价美元成本
- ChatGPT/Codex credits 估算
- 无公开价格模型的独立用量

应用不会上传日志，也不会把提示词或回复正文写入自己的数据库。逐调用 token
统计和已经识别的 Fast/Priority 证据会持久保存在本地 SQLite，不随 Codex 滚动日志删除。
源日志消失、被清空、截断或移入归档后，已采集的逐调用用量、会话标题、父子关系和
价格快照继续保留；重扫以合并更新为主，不用当前文件内容替换整段历史。明确重复的
回退记录或子会话继承内容仅标记为不参与统计，原记录和价格引用仍保留。

Light 风格网页包括用量总览、模型定价、每日明细、项目用量、会话用量和重置日期。项目统计使用
会话当时的工作区路径，并将仓库子目录和 Codex worktree 合并到对应的 Git 主仓库；项目页
可查看全部项目总量以及单个项目的每日 Token 和 API 等价美元。
项目总量图、项目汇总行和会话标题点击一次会选中并加载下方明细；再次点击已选中的项目或会话，
会滚动到对应的明细区域。项目的选中状态会同时显示在两张总量图和汇总表中。

“会话用量”支持按 API 等价成本、Token 或 Fast 加价排序，并搜索标题、项目和会话 ID。
排行默认只显示父会话，汇总父会话自身及所有层级子会话在所选区间内的用量。
点击标题左侧的 `>` 可展开，分别查看父会话本身和各子会话的自身用量；排序及分页以父会话为单位，
搜索也会匹配子会话标题和 ID。点击父会话查看合计趋势与调用明细，点击展开项查看该会话自身明细。
归属读取日志和本地线程数据库中明确的父会话 ID，并保存在统计数据库；缺少关系的旧子代理
独立显示“归属未知”，不会按项目或时间猜测。父会话在区间内没有自身调用时，仍显示其子会话合计。
用量总览的模型统计、每日明细、项目汇总及会话用量表格支持点击名称以外的表头切换升序、
降序，默认按 API 等价成本降序。未知金额始终排在已知金额之后；会话和调用明细先排序再分页，
调用明细的总计行固定在顶部。切换筛选条件会保留当前表格的排序选择。
点击会话可查看区间内的用量趋势和逐调用明细，每页 50 条。标题仅从 `session_index.jsonl`
和本地 `state_*.sqlite` 的线程元数据读取，缺失时显示缩短的会话 ID；不读取消息正文。
会话标题会保存在本机数据库，归档或删除源日志后仍可显示。

统计页面支持按天 / 按小时切换，作用于总览、明细、项目和会话趋势；小时按应用时区归桶，
仅显示有调用的小时。CSV 导出保留当前粒度、日期时分和价格口径。

未指定日期范围时，默认查看应用时区的今天，时间为 `00:00` 至 `23:59`。
右上角的日期范围按钮会打开双月日历，默认左侧为上个月、右侧为本月：
依次选择开始日期、结束日期后自动更新统计，
无需点击应用。支持跨月范围、同一天、翻月和键盘方向键；关闭日历会取消未完成的选择。
开始和结束时间支持小时、分钟，默认分别为 `00:00`、`23:59`。日期选完或修改有效时间后
自动更新统计；同一天的结束时间不能早于开始时间。快捷日期范围会恢复全天默认时分。
以应用设置的时区判断“今天”，未来日期置灰不可选，键盘导航和翻月也受此限制。
日历中加粗的日期表示当前账号已确认的额度重置日，悬停可查看对应的额度窗口。

左侧“重置日期”页面列出当前账号保存的重置时刻，区分已确认和推测时间。成功读取已使用的
额度窗口后，会用下次重置时刻减去窗口长度，记录当前周期开始的推测时间；未使用的滚动
窗口不据此推测，缺失的更早历史周期不会补造。同一时刻的多个额度窗口合并显示。
列表顶部提供可选择的“今天”，显示当前时间前两分钟的日期和时间，进入页面或刷新记录时更新；
选中后固定该时刻，直到完成区间选择或取消选择。“今天”不计入重置记录数量。
点击任意两个不同的时刻会自动按先后排序并跳转到用量总览。此范围保留完整时间戳，
包含开始时刻，不包含结束时刻，避免把下一周期的用量计入；普通日历时分筛选仍包含整个
结束分钟。刷新、切换页面和 CSV 导出保留该精确范围；手动改动日期或时分会恢复分钟筛选。

日志中的逐调用完整 UTC 时间戳一直保存在数据库，包含源日志提供的秒和小数秒精度。
总览、每日明细、项目统计和 CSV 导出都按应用时区的具体时间范围筛选；结束时间包含
所选分钟的全部秒数。各统计接口支持 `start_time=HH:MM`、`end_time=HH:MM`，未提供时
仍按全天统计。修改时间也会保存在页面 URL，刷新、切换页面和前进后退时保留。

左侧菜单底部显示当前 Codex 登录账号的套餐、额度剩余百分比与重置时间。
账号额度独立于历史日期筛选，页面首次打开读取一次，之后可点击“刷新额度”手动更新。
切换页面或回到窗口时不会自动读取，也不再显示更新时间和 Credits 余额。
点击“可用额度重置次数”可查看每次 banked reset 的到期时间；如果服务端只提供次数，
浮窗会说明到期时间暂未提供。有可用重置将在 72 小时内到期时，该次数和“刷新额度”按钮变红。

## 当前账号额度

实时额度通过本机 `codex app-server` 的 `account/read` 和 `account/rateLimits/read` 查询
服务端，复用所选 `CODEX_HOME` 的 Codex 登录。需要可用的 Codex CLI 和 ChatGPT 登录；
API Key 或 Bedrock 登录不会提供 ChatGPT 订阅额度。应用不读取、保存或向浏览器传递 OAuth
token；CLI 自己管理认证及运行时文件。此查询会联网获取账号额度，不上传会话日志。

额度窗口按服务端实际提供的长度显示，支持多组额度；不假定每个套餐都有 5 小时和每周
两种额度。剩余比例为 `100 - usedPercent`，不是从本地 token 或等价美元估算的。服务端
缺失的字段显示为未知或未提供。刷新失败时清除旧账号额度，避免切换登录后误显示旧数据。
总览和模型表中的历史 Credits 用量估算独立于当前账号额度。
账号身份与实时额度读取分开：可以识别当前账号时，即使额度接口失败，仍显示该账号
已保存的重置和美元历史。无法识别当前账号时，按日志目录加载“上次保存的账号”的
离线档案，并明确标注来源和最后成功读取时间；离线百分比不会作为当前剩余额度显示。
确认切换到另一账号后，只查询新账号的历史。认证错误最多由 CLI 刷新登录后重试一次。

CLI 优先使用指定的可执行文件，然后从 PATH 查找。Windows 下还会自动查找 Codex
桌面应用附带的 `%LOCALAPPDATA%\OpenAI\Codex\bin\<版本>\codex.exe`，因此双击启动
时无需把 CLI 加入系统 PATH。每次刷新重新查找，可适应桌面应用更新后的版本目录变化。
也可手动指定可执行文件：

```powershell
$env:CODEX_TOKEN_REPORT_CODEX_BIN = "C:\path\to\codex.exe"
```

`GET /api/quota` 返回最多缓存 60 秒的账号额度；`POST /api/quota/refresh` 强制刷新。
实时额度缓存仅保存在内存中。读取有 30 秒超时，完成或超时后关闭所启动的 app-server。
每次成功读取的公开额度字段另行永久保存，包括 0% 或暂时无法换算美元的窗口；
账号身份仅保存哈希，归档按日志目录和账号隔离。离线查看、失败的读取和切页不新增读数。

从启用重置判断起，每次成功刷新会把最近的额度快照和已确认重置事件保存在本地 SQLite。
账号身份仅保存哈希，不保存邮箱或认证信息；不同账号独立记录。正常重置需要前后读数的
周期边界一致且已过重置时间；提前重置需要用量下降、新周期开始时间落在观察间隔中，
并等待至少 60 秒后的第二次一致读数。切换套餐、额度窗口长度变化、缺失身份或时间字段，
不会据此判定重置。首次读数建立基线，并可记录当前已使用窗口开始时刻的推测值；跨过
多个未观察周期时不会补造更早的重置记录。日期按应用时区显示，刷新页面和重启应用后
仍保留记录。判断随页面初次读取和手动刷新额度进行；不会自动轮询，未能确认的日期不会加粗。

左侧“额度等价美元”按当前窗口的周期开始至最近一次额度读取时刻，分别显示已用百分比、
这段期间的 API 等价美元、每 1% 美元、整窗 100% 与剩余额度的等价估算。起点优先使用
相近的已保存重置记录，否则以“下次重置时刻 − 窗口长度”推测；推测起点会单独标明。
范围包含起点、不包含额度读取时刻，独立于普通日历筛选。可切换快照估算和当前价格重算。
“刷新并换算”先扫描新日志，再刷新账号额度；切页只用最近一次额度快照，不联网重新读取。

每 1% 美元 = 期间 API 等价金额 ÷ 已用百分比；整窗美元 = 每 1% 美元 × 100。
这是按本周期模型、缓存与 Fast 使用情况外推的 API 等价估算，不是订阅账单或额度售价。
多个窗口可能覆盖相同调用，不能相加。部分新版日志带有 `creator_account_id` /
`creator_user_id`，但当前统计器尚未解析这些字段，调用统计仍不按账号划分。因此金额
只对应此日志目录内的 Codex 调用；同一目录切换过账号时，换算可能混入其他账号的调用，
不能据此验证当前账号的精确消耗，也不包括其他设备或云端使用。调用尚未按额度组归属，
其他额度组显示无法分配调用。未定价调用不计入金额；有已定价调用时，仍按已知金额除以完整已用百分比，
计算每 1%、整窗和剩余额度，并标为已知金额估算；0%、缺少本地调用、全部调用未定价、
缺失时间或读数已跨过重置时刻时，不强行推算。

从启用历史保存起，每次成功读取可识别账号的额度，会把该次已用百分比、消耗的已知
API 等价美元、每 1%、整窗和剩余估算保存到本地 SQLite，两种价格口径分别保留。
历史按账号、套餐、额度窗口和周期分组；重置和重启不会删除旧周期。页面下方的
“周期历史”显示上一周期重置前最后一次实际读到的百分比和消耗金额，并可查看每次读数。
它不代表重置瞬间的最终用量，未观察到的额外消耗不会补造；历史重置时刻保留该读数当时的
计划时间，提前重置后也不会把原计划时间冒充实际边界。未使用且无已知起点的滚动
窗口不据此制造历史周期。失败或无法识别账号的读取不新增额度读数；成功识别另一账号时，
仅查询该账号的历史。
无法识别账号时可以查看已保存的离线档案；它明确标为上次保存的账号，不代表当前登录。

历史金额保留当次计算结果，之后新增日志、改变价格或重新扫描不会覆盖；切换价格口径
查看当次保存的另一组估算，不重算旧记录。只有成功读取额度才会新增读数，切换页面不
重复保存，也不会自动轮询。启用前仅有重置时间的旧周期，不能补出缺失的百分比和金额。
实时读取失败时，“额度等价美元”显示最后保存的换算和原读取时间，不用新日志或新价格
修改这次读数的金额，也不把旧周期标为当前周期。旧版本没有日志目录索引的历史也可
离线查看，明确标为“旧版本本地账号档案（日志目录归属未确认）”；成功读取后才建立
账号与日志目录索引，不据此猜测旧读数属于当前账号或当前日志目录。

“会话用量”的调用明细下方另有“账号额度读数”：扫描日志中的额度百分比、窗口和当次
计划重置时间，按会话保存，支持主会话和子会话合并查看。这些是该会话中观测到的账号
整体读数，不能把前后百分比变化当作该会话的精确消耗；它们不猜测账号归属，也不作为
当前账号的已确认重置日期。日志清空、归档和重启后仍可查看已采集的读数。

只能保存已经扫描或成功读取到的数据。清空前尚未扫描的日志、其他设备用量，以及未被
观察到的额度和重置时刻无法补回。请保留统计数据库；仅保留代码或源日志目录不能替代它。

`GET /api/quota/value?price_mode=snapshot|current` 复用已缓存额度读数进行换算。
`GET /api/quota/value/history?price_mode=snapshot|current&offset=0&limit=20` 返回当前账号的
周期历史；`GET /api/quota/value/history/{cycle_id}?price_mode=snapshot|current` 返回周期内
的读数详情。这两个接口只查询本地历史，不刷新实时额度。
`GET /api/sessions/{key}/quota?offset=0&limit=50&include_children=true|false` 返回该会话
已保存的账号额度读数；不读取源日志或实时额度，重置时间为 UTC ISO 时间戳。

参考：[OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server)
及 [CodexBar 的 Codex 数据源说明](https://github.com/steipete/CodexBar/blob/main/docs/codex.md)。

## 快速开始

需要 Python 3.12 或更新版本、`uv`，以及本机可读取的 Codex 日志目录。下载或克隆仓库后，
在仓库根目录运行下列命令。浏览器版本不需要安装 `desktop` 或开发依赖；实时账号额度
另需可用的 Codex CLI 和 ChatGPT 登录，已有历史查看与本地日志统计不依赖实时额度查询。

当前验证环境为 Windows。下面同时提供 macOS / Linux 的浏览器版本启动方式，但尚未
完成这两个平台的实际运行验证；桌面窗口外壳的 macOS / Linux 支持也未实测。

### Windows（PowerShell 7）

```powershell
uv sync --locked
uv run codex-token-report
```

默认打开 `http://127.0.0.1:8765`。也可以双击或从 PowerShell 启动仓库附带的
`codex_ana.bat`；该启动器仅适用于 Windows，并使用 `http://127.0.0.1:18765`：

```powershell
.\codex_ana.bat
```

### macOS / Linux（终端）

两者使用相同的浏览器服务入口，分别在 macOS 的终端或 Linux 的 shell 中运行：

```sh
uv sync --locked
uv run codex-token-report
```

默认地址同样是 `http://127.0.0.1:8765`。实时额度查询需要当前终端的 `PATH` 中存在
`codex`，或通过 `CODEX_TOKEN_REPORT_CODEX_BIN` 指定可执行文件；Windows 桌面版 CLI
的自动查找逻辑不适用于 macOS / Linux。例如在这两个平台的 shell 中设置：

```sh
export CODEX_TOKEN_REPORT_CODEX_BIN="/path/to/codex"
```

无图形环境或希望自行打开浏览器时，三个平台都可使用：

```text
uv run codex-token-report --no-browser
```

此选项只关闭自动打开浏览器，服务仍默认监听本机 `127.0.0.1`。远程主机上运行时，
可以使用 SSH 端口转发访问该本地服务。

更新代码后，需要关闭旧服务并重新运行 `codex_ana.bat`（或上述启动命令），再刷新页面。
后端不会自动重载；若页面与运行中的后端版本不匹配，统计区会明确提示重启。

首次启动扫描所选 Codex 目录中的 `sessions`、`archived_sessions` 和 `logs_2.sqlite`。
默认读取环境变量 `CODEX_HOME`，未设置时使用当前用户主目录下的 `.codex`：Windows
为 `$env:USERPROFILE\.codex`，macOS / Linux 为 `~/.codex`。通过 `--codex-home` 可以覆盖。

统计数据库默认位于 Windows 的 `$env:LOCALAPPDATA\CodexTokenReport\usage.sqlite3`，
macOS / Linux 为 `~/.local/share/codex-token-report/usage.sqlite3`。可通过 `--data-dir`
或 `CODEX_TOKEN_REPORT_DATA_DIR` 指定持久数据目录；不要把它放进将被清空的日志目录。

## 常用命令

只更新本地统计数据库，不启动网页：

```powershell
uv run codex-token-report --scan-only
```

指定 Codex 目录和数据目录（Windows / PowerShell）：

```powershell
uv run codex-token-report `
  --codex-home "$env:USERPROFILE\.codex" `
  --data-dir "$env:LOCALAPPDATA\CodexTokenReport"
```

macOS / Linux 对应命令：

```sh
uv run codex-token-report --codex-home "$HOME/.codex" --data-dir "$HOME/.local/share/codex-token-report"
```

使用可选桌面窗口外壳（依赖 pywebview；macOS / Linux 未实测，浏览器版本可独立运行）：

```powershell
uv sync --extra desktop
uv run codex-token-report-desktop
```

## 每日自动更新

以下脚本仅适用于 Windows，会创建一个计划任务，默认每天 23:55 执行增量扫描：

```powershell
pwsh -File .\scripts\install_scheduled_task.ps1 -ProjectPath $PWD
```

它只负责更新统计数据库，不会在后台一直运行 Web 服务。

Web 服务运行时还会默认每 60 分钟增量扫描一次。可通过环境变量调整或关闭：

```powershell
$env:CODEX_TOKEN_REPORT_SCAN_INTERVAL_MINUTES = "30" # 设为 0 可关闭
```

首次扫描在后台执行，不会阻塞 Web 端口启动；可通过 `/api/health` 的 `scan.state`
查看 `queued`、`running`、`complete` 或 `error` 状态。

增量扫描只读取已扫描文件后来追加的完整 JSONL 行；文件被截断、解析模式变化，或旧版本
数据库需要升级时会自动完整重扫。会话从 `sessions` 移入 `archived_sessions` 后使用稳定的
会话 ID 识别，不会因路径变化重复累计。

Ultra 模式产生的 sub-agent 日志可能包含从父任务复制的历史。扫描器读取
`session_meta.subagent_history_start_ordinal`，只统计该 sub-agent 自己开始执行后的 token
记录，避免父任务与多个 sub-agent 对同一段上下文重复计数。没有该字段的旧日志仍按原记录
统计，并保留 `is_subagent` 标记供审计。

## 数据与隐私

- 扫描器逐行读取 JSONL，只保留时间、模型、token 数、匿名事件 ID、稳定会话 ID、
  sub-agent 标记、父会话 ID、来源文件路径和项目路径。
- `logs_2.sqlite` 始终以 SQLite 只读模式打开，只提取 `turn_id`、模型和
  `service_tier=priority` 证据，不保存请求正文。
- 不保存用户消息、助手消息、命令输出或推理正文。
- Web 服务默认只监听 `127.0.0.1`。
- 数据库默认位于 Windows 的 `$env:LOCALAPPDATA\CodexTokenReport\usage.sqlite3`；
  macOS / Linux 默认使用 `~/.local/share/codex-token-report/usage.sqlite3`。
- 逐调用记录没有自动清理期限；删除源 JSONL 不会删除已经采集的统计。
- 删除统计数据库会丢失已保存历史，只能从仍存在的源日志重新扫描；应用不会修改 Codex 原始日志。

### 备份与跨机迁移

统计数据库使用 SQLite WAL 模式。迁移前停止所有 Web 服务、桌面窗口和扫描进程，
并暂停可能启动扫描的计划任务，再复制整个数据目录；不要在服务运行时只复制
`usage.sqlite3`，也不要遗漏或手动删除仍存在的 `usage.sqlite3-wal` / `usage.sqlite3-shm`。
如果必须在线备份，使用 SQLite 的 backup API 生成一致快照，再迁移该快照；直接复制
正在写入的数据库文件不能保证备份完整。

在目标机器配置 `--data-dir` 或 `CODEX_TOKEN_REPORT_DATA_DIR` 指向复制的数据目录，
保留一份原始备份后再启动。已扫描的调用、会话元数据和价格快照随数据库保留，不必
依赖原始日志仍存在。数据库包含本地会话标题及源文件、项目路径，属于个人使用数据，
不要随代码提交或公开上传。

目前额度档案的 `home_key` 来自解析后的 `CODEX_HOME` 路径，`account_key` 也包含该
路径与账号身份的哈希。跨机器、跨操作系统或改变日志目录路径后，即使登录同一账号，
也可能生成不同的索引和账号键。因此复制数据库能保留旧额度记录，但新目录的页面未必
能自动显示或合并这些历史；新的成功读取会按新目录归档。目前没有额度账号索引的跨机
迁移或重新绑定工具，不能把“数据库已复制”等同于“当前账号额度历史已衔接”。

## 价格口径

首次启动使用的内置价格表位于
[`src/codex_token_report/data/pricing.json`](src/codex_token_report/data/pricing.json)，包含查询日期和
OpenAI 官方来源链接。

网页中的“刷新价格”会一次获取 `https://models.dev/api.json`，只匹配 `openai` 供应商下的
准确模型 ID，并把有效的 USD / 1M token 单价缓存在本地 SQLite。价格选择顺序为手工覆盖、
models.dev 有效缓存、内置价格。目录缓存包含尚未使用的 OpenAI 模型，新出现的模型
可立即从缓存查价。缺失的缓存读写价格使用内置单价补充，没有内置值时保持未知；
不再使用旧的官方文档价格补缺，也不会借用其他供应商的同名模型价格。

初次日志扫描完成后会在后台检查价格缓存；有效 models.dev 缓存 24 小时内复用。
启动及后台扫描完成后检查缓存。缓存过期或有模型缺少单价时可刷新；自动重试有
15 分钟冷却，多个进程共享同一冷却记录。刷新失败继续使用上次有效缓存；空目录
不会替换有效缓存，目录移除的旧模型保留最后有效价格。手动“刷新价格”可强制刷新。
旧版本缓存会在下一次启动时补齐目录。仅执行 `--scan-only` 不联网刷新。
`/api/health` 的 `pricing_refresh.state` 显示 `queued`、`running`、`complete`、`partial`、
`error` 或 `skipped` 状态。

统计页面可切换“当前价格重算”与“快照估算”，默认使用快照估算。
价格口径和按天 / 按小时切换集中在日期筛选栏内，已有 URL 显式指定的口径仍会保留。
应用从启用此功能起保存有效价格版本（包括手工覆盖、Fast、Credits 和长上下文倍率），
每次扫描为新请求固定对应的已保存版本。修改价格、重扫、归档和重启不会覆盖既有价格引用。旧快照中程序自动填入的 Fast 1x
默认值按独立倍率表纠正，保留其基础单价、日期和手工倍率。
请求时间早于最早保存的价格版本时，使用首次可用价格回填，并明确标为估算；无法据此确认
当时官方价。未知模型在原快照中仍保持未知，之后新增定价只影响当前价格重算。

金额表示按价格表查询日的 API 文本 token 单价换算的等价成本，不是 ChatGPT 订阅的最终账单。
扫描器参考 CodexBar 的实现，将 `logs_2.sqlite` 中 Fast/Priority 请求的 `turn_id` 与 JSONL
token 记录关联，再逐请求应用以下倍率：

- API Fast 倍率独立维护，参考 CodexBar：GPT-5.4、5.4-mini、5.6 Sol/Terra/Luna、
  6 Astra 为 2 倍；GPT-5.5 为 2.5 倍。GPT-6.1 Sol 根据官方模型文档补充为 2 倍。
- 没有已知 API Fast 倍率的模型保持价格未知，不默认成 1x。界面和 CSV 分别显示
  已知加价与未知 Fast 调用数；基础单价已知时仍保留 Standard 等价金额。
- 订阅内额度与 API 美元不是同一口径。官方 Codex Fast 消耗订阅内额度为 Standard 的
  2.5 倍（多 150%）；购买的 credits / Enterprise 按用量计费为 2 倍。客户端的 speed
  倍率是速度提示，不能拿来计算额度。没有公开的模型 Credits 基础价格时保持未知。

档位证据来自请求、Submission 以及运行时 `feedback_tags.tags_json.service_tier`，
按 turn ID 关联。升级后自动重读现存 trace，补上继承 Fast 设置的轮次，同时保留历史证据。

无法从本机 trace 数据确认档位的历史请求按 Standard 基础价估算，并在界面和 CSV 中计入
“档位未知”；不会根据当前 `config.toml` 把全部历史记录猜成 Fast。

下列因素不会被伪装成精确金额：

- 套餐内含额度和 credits 的实际购买价格
- 企业折扣或合同价格
- 没有公开价格的内部模型，例如 `codex-auto-review`
- 第三方模型
- Web search、容器等工具调用费用
- Batch、Flex 或区域处理倍率

长上下文优先使用 models.dev 的明确 context tier 阈值与单价；仅有旧
`context_over_200k` 时使用 200K 阈值，缺失时保留内置规则。按整次请求计算基础成本，
再应用该请求的 Fast/API Priority 倍率。手工覆盖继续使用本地长上下文倍率规则。
